## 一、这套课件解决什么问题

课程标准的「学习目标」是抽象的能力描述，课堂上真正需要的是**能按顺序讲、能直接发下去练**的材料。本仓库把 13 个模块拆成 67 个知识点，另设 1 个调试工具专题（第 5A 节，7 个技能）与 2 个本地 AI 拓展章（第 14—15 章，14 个技能），共 88 个知识点，每章统一按四段式组织，教师打开即可照着讲，学生打开即可照着敲。

本轮知识点体系优化后，**既有 74 个知识点每个再补「原理补充 / 变式代码 / 实操步骤 / 常见问题 FAQ」四段**：普通章节知识点统一为 .1—.6 六小节，第 5A 节为 .1—.5 五小节，第 14—15 章为七小节。所有增补由脚本**纯插入**完成，讲义原文的文字、编号、数值与结构一字未动，并由脚本逐行证明了原文完整保留。

**几个明确的设计约束：**

1. **不超纲**——每章代码只使用该章及之前学过的语法。例如第 9 章讲异常时不允许出现自定义异常类（`class` 在第 11 章），第 4 章讲字符串时不出现列表推导式。每章开头都写明「知识点范围」与「本章不引入什么」。
2. **场景真实**——所有案例、练习、示例都落在智慧交通与智能网联汽车业务上：车流密度、平均车速、通行能力、信号配时、ETC 计费、日志统计、碰撞判定，而非抽象的 `a + b`。
3. **输出可验证**——每段代码都给出「预期输出 / 运行结果」，由脚本真实执行后采集，与代码逐字对应（交付前用 `verify_demos.py` 全量复跑比对，共 **195 条**：169 个内联示例〔81 随堂示例 + 88 变式示例，其中 74 个为本轮新增〕+ 26 个独立 `.py` 文件〔05A 节 14 个 + 第 14—15 章 12 个〕）。
4. **三载体同源**——`.py` 是唯一代码源，`.md` 与 `.ipynb` 由脚本从它生成，改一处即可全量同步，避免「讲义代码」与「可运行代码」两张皮。
5. **本地 AI 全离线**——第 14—15 章只用标准库，模型推理由本机 Ollama 承担；案例默认离线演示模式，`--live` 才连 `127.0.0.1:11434`；首次 `ollama pull` 需联网，之后可断网运行。

## 三、每章怎么讲（四段式）

| 顺序 | 板块 | 内容构成 | 课堂用途 |
|---|---|---|---|
| 1 | **第一部分　知识讲解** | 每个知识点含「核心概念 / 语法要点 / 常见易错点 / 随堂示例」 | 讲授，配合板书与提问 |
| 2 | **第二部分　代码示范** | 案例 ×2：任务情境 → 任务要求 → 参考代码（带注释）→ 运行结果 → 代码解读表 | 教师演示，学生跟做 |
| 3 | **第三部分　布置练习** | 练习 ×2：题目 → 要求 → 提示 → 自检要点（**不含答案**） | 课堂练习 / 课后作业 |
| 4 | **第四部分　习题答案** | 答案 ×2：参考代码 → 运行结果 → 解析 → 常见错误 → 评分要点 | 讲评，先做后看 |

章首另有「本章学习路径」（索引表 + 知识点与代码对照表）与「教学提示（教师用）」（建议课时、讲解主线、学生卡点、课堂活动）；章末有「本章小结」「自检清单」「前后章节衔接」。

**随堂示例**写在每个知识点之后，固定三步：

- **核心要点**——一句话说明这个例子验证什么，不引出别的概念；
- **代码**——10 行上下，带中文行注释，自成一体（不依赖 `input()`、不开图形窗口、随机量固定 `seed`）；
- **预期输出**——该代码真实执行的 stdout，逐字给出。

示例本身就是 Notebook 中的代码单元格，点一下即可运行并当场核对。

## 六、五个容易踩的坑

1. **`input()`**：第 2、3、4、9 章的代码含 `input()`。在 JupyterLab 中运行后，单元格下方会出现输入框，按各段「运行结果（示例输入：…）」里给出的值填写即可。
2. **多文件（第 10 章）**：标为「模块文件」的代码块带 `%%writefile` 魔术命令，运行一次才会把代码写盘为同名 `.py`；随后运行调用程序才能 `import` 成功。程序包练习需在章节目录用 `python -m traffic_pkg.main` 方式运行。
3. **图形窗口（第 13 章）**：`turtle` 属标准库，`pygame` 需安装。二者都会弹出独立窗口，**必须手动关闭**才能继续，否则内核被占用、后续单元格一直等待。
4. **调试（第 5A 节）**：断点只在 **`F5` 启动调试**时生效，用 `Ctrl+F5` 直接运行不会停；若断点显示为**灰色空心圆**，说明解释器没选或调试目标不是当前文件（命令面板 → `Python: Select Interpreter` 重新选择）。本节所有 `示例5A…` / `练习5A…` 文件都要在 Trae 里打开再按 `F5`，在 Notebook 中跑只能看到结果、看不到过程。
5. **本地 AI（第 14—15 章）**：默认输出来自「离线演示模式」的确定性桩数据，**不是模型推理结果**——务必看输出首行的「运行模式」。加 `--live` 前先 `ollama serve` 并保持窗口；模型名要与 `ollama list` 逐字一致（含 `:3b` 等 tag）；4GB / 6GB 显存必须加 `--vram 4` 换 `moondream`。首次 `ollama pull` 需联网，之后才能断网推理。

## 七、维护与二次开发

`.py` 文件是唯一代码源，`.md` 与 `.ipynb` 由构建脚本生成。修订顺序不可颠倒：

```
改 .py  →  sync_md_code.py（同步讲义代码块）
        →  build_notebooks.py（重建 notebook）
        →  build_index.py（重建课程首页）
        →  verify_demos.py（全量执行 195 条示例与案例，逐字比对输出）
```

改第 1—13 章与 05A 节的随堂示例只改 `.workbuddy/build/demos.py`，然后：

```bash
python3 .workbuddy/build/insert_demos.py --refresh   # 重算预期输出，原地覆盖
python3 .workbuddy/build/build_notebooks.py
python3 .workbuddy/build/verify_demos.py
```

`.workbuddy/build/` 下的脚本清单：

| 脚本 | 作用 |
|---|---|
| `demos.py` | 第 1—13 章与 05A 节 67 个随堂示例的唯一源头（章节、知识点号、标题、核心要点、代码） |
| `insert_demos.py` | 执行示例采集 stdout，写入/刷新 md 中的「随堂示例」小节 |
| `sync_md_code.py` | 把 md 中 `python 文件名.py` 围栏内容同步为磁盘 `.py` 内容（章节清单含 14 / 15） |
| `build_notebooks.py` | 由 md 生成同构 notebook、生成底部章节跳转导航，并校验代码单元与 `.py` 一致（章节清单含 14 / 15） |
| `build_index.py` | 生成课程首页 `00_课程索引.ipynb`（章节目录含 14 / 15） |
| `verify_demos.py` | 交付前校验 **195 条**：169 个内联示例 + 26 个独立 `.py` 示例/练习/答案，逐条运行并与文档输出逐字比对 |
| `enrich_chapters.py` | 74 个既有知识点的四段增补注入器：`--check` 实跑全部变式代码、`--apply` 纯插入写入并逐行证明原文未改、`--undo` 精确回滚 |
| `enrichment/ch*.py` | 14 个章节的增补数据源（原理 / 变式代码 / 实操步骤 / FAQ），是 74 个新增变式示例的唯一源头 |

> 第 14—15 章的示例与 74 个新增变式示例（围栏形如 `demo1-1b`）不走 `demos.py`：前者直接写在各章 `案例与练习.md`，后者的唯一源头是 `.workbuddy/build/enrichment/ch*.py`。修改变式示例后先 `--undo` 再 `--apply`（或只用 `--check` 校验代码可跑），随后照常重建 Notebook。新增章节时需同步四个脚本的章节清单，详见 `00课程说明与索引.md` 第八节。

## 八、常见问题

**Q：还没装 Python 能给个在线预览吗？**
可以，先看各章 `案例与练习.md`（纯文本，内容与 Notebook 一致），装机后再跑代码。

**Q：运行后中文显示成乱码 / 读写文件报 `UnicodeDecodeError`？**
本仓库全部文件为 UTF-8，读写时显式写 `encoding="utf-8"`。Windows 终端如仍异常，先执行 `chcp 65001`。

**Q：`turtle`/`pygame` 报 `ModuleNotFoundError`？**
`turtle` 是标准库，报错多为解释器环境不一致；`pygame` 需 `python3 -m pip install pygame`（注意用与 Jupyter 内核相同的解释器）。

**Q：`案例与练习.md` 里的代码和 `.py` 不一样？**
说明改完 `.py` 忘了同步。执行 `python3 .workbuddy/build/sync_md_code.py` 后重建 notebook 即可。

**Q：第 15 章没装 Ollama、没有 RTX 3050 能上课吗？**
能。两个案例默认走**离线演示模式**，只用标准库，不联网、不占显卡，输出与讲义逐字一致，可完整讲通「找文件 → 转码/清洗 → 发请求 → 校验 → 统计 → 落盘」的流水线。加 `--live` 才需要本机 Ollama 与显卡；真实 GPU 推理的准确率、耗时与显存占用需按讲义 15.7 在本机验收。

**Q：`--live` 提示 `Connection refused` 或 `model not found`？**
前者先 `ollama serve` 并保持终端窗口，再 `curl http://127.0.0.1:11434/api/version` 确认服务在（程序也会自动降级回演示模式，不会卡死）；后者用 `ollama list` 逐字核对模型名，注意 `:3b`、`:latest` 这类 tag 不能漏。首次 `ollama pull` 需要联网，之后才能断网推理。

**Q：可以直接拿去做校本教材吗？**
可以用于教学与教研，改动请保留本仓库出处；正式出版或商业用途请先联系作者。
