## 1.1 场景导入：交通信息的第一层界面

智慧交通系统的第一层人机界面就是"屏幕"：路侧可变情报板、停车场入口屏、车载仪表、调度中心大屏。这些界面本质上是**按固定版式输出若干行文字**——上下有分隔线、标题居中、条目编号、字段对齐。

因此第一个程序不急着计算，而是先把"版式"立起来。掌握 `print()` 的换行、对齐与转义处理，是把交通信息"排好版"的第一步。本章两个案例分别对应两种典型版式：

- **案例 1-1**：情报板式——固定行数、上下分隔线、逐条编号，对应知识点 1.1、1.2、1.4；
- **案例 1-2**：屏显式——多行须知整段输出、三列字段对齐、路径含反斜杠，对应知识点 1.3、1.2、1.4。

## 1.2 知识点 1.1　输出语句与字符串字面量

### 1.2.1 核心概念

程序与外界交流的三种方式中，最基础的是**输出**（另外两种是输入与文件读写，分别在第 2 章、第 8 章）。Python 用 `print()` 完成输出：

- `print` 是**函数**，后面跟一对圆括号，括号内写要输出的内容；
- 括号内写的东西叫**参数**，本章只有一个参数：一段**字符串**；
- 字符串必须用引号括起来，引号内的内容原样输出（不含引号本身）；
- 每次调用 `print()` 输出完内容后**自动换行**，所以 5 条 `print` 就是 5 行。

**原理补充（概念深化）**：`print` 并不是语言里的特殊句式，而是一个**内置函数**：解释器遇到 `print(...)` 时先求出括号内每个表达式的值，再把它们交给输出流。这解释了三件事：第一，引号只是**构造字符串字面量**的记号，字符串对象里并不包含引号，所以输出看不到它们；第二，多参数之所以自动空一格，是因为 `print` 默认用 `sep=" "` 连接各参数，并在末尾追加 `end="\n"`；第三，`print` 会先把非字符串参数转成可显示的文本，所以 `print(62)` 与 `print("62")` 看起来一样，但参与运算时完全不同。理解「先求值、再转换、最后写出」这条链，后面学 f-string 与文件写入时才不会把「显示格式」和「数据本身」混为一谈。

### 1.2.2 语法要点

| 语法形式 | 说明 | 输出 |
|---|---|---|
| `print("文本")` | 双引号字符串 | 文本 |
| `print('文本')` | 单引号字符串，与双引号等价 | 文本 |
| `print("")` | 空字符串，输出一个空行 | 空行 |
| `print("a", "b")` | 多参数用逗号分隔，中间自动补一个空格 | `a b` |

**引号的三种选择**：

1. 文本本身不含引号：单引号、双引号随意，推荐统一用双引号；
2. 文本内含双引号：外层用单引号，如 `print('屏幕显示"限速 60"')`；
3. 文本内含单引号：外层用双引号，如 `print("Don't stop")`。

### 1.2.3 常见用法与易错点

| 情况 | 错误写法 | 后果 | 正确写法 |
|---|---|---|---|
| 漏写引号 | `print(智慧交通)` | `NameError: name '智慧交通' is not defined` | `print("智慧交通")` |
| 引号不成对 | `print("提示)` | `SyntaxError`，后续整段都无法运行 | 成对书写，编辑器会高亮配对 |
| 中文标点 | `print（"提示"）` | `SyntaxError: invalid character` | 括号、引号、逗号一律用**英文半角** |
| 用中文引号 | `print(“提示”)` | `SyntaxError` | 用 `"` 或 `'` |
| 误以为引号会输出 | —— | 输出中不含引号，属正常现象 | 需要引号本身时用 `\"`，见 1.3 |

> **课堂提示**：`SyntaxError`（语法错误）在程序**运行前**就会被发现，报错信息会指出行号；而 `NameError` 是运行到该行才出现。初学者九成的报错来自中文标点与引号不成对，先查这两项。

### 1.2.4 随堂示例：四种 print 写法一次跑通

**核心要点**：验证 `print()` 的四种基本写法：单引号、双引号、多参数（自动补空格）、空参数（输出空行），并确认引号本身不会出现在输出里。

### 1.2.6 常见问题 FAQ

| 现象 | 根因 | 处理 |
|---|---|---|
| 输出里带着引号 | 把引号写进了字符串内部，如 `print('"限速 60"')` | 引号只用来定界，需要显示引号时才在字符串里再写一层 |

## 1.3 知识点 1.2　注释

### 1.3.1 核心概念

注释是写给人看的说明，**不参与运行**。它的价值在于让三个月后的自己、以及批改作业的教师，能在不读代码细节的情况下知道"这段在干什么"。

Python 有两种注释：

1. **单行注释**：以 `#` 开头，直到行尾都是注释；
2. **文档注释（三引号注释）**：用三个引号包住的一段多行文字，放在文件开头用于说明程序名称、作者、日期、功能。

**原理补充（概念深化）**：注释不是「被忽略的文字」那么简单：Python 在真正编译之前会先做**词法分析**，扫描到 `#` 就把从该字符到行尾的内容整体丢弃，因此注释里写什么都不会影响字节码，也不会占用运行时内存。这带来两个实践结论：其一，注释可以安全地临时「关掉」一行代码来做对照实验（调试时叫「注释掉」），但更推荐用第 5A 节的断点，因为不会留下被遗忘的死代码；其二，三引号字符串只有在**未被赋值给任何变量、且独立成句**时才被解释器当作文档字符串保留，写在表达式位置它仍是真实对象，会参与运算。也就是说，「三引号注释」严格讲并非语法层面的注释，只是约定用法。注释真正该写的是「为什么这样做」，而不是复述代码在做什么。

### 1.3.2 语法要点

| 形式 | 写法 | 位置 | 用途 |
|---|---|---|---|
| 单行注释 | `# 输出标题` | 可独占一行，也可跟在语句后 | 解释某一行/某一段 |
| 行尾注释 | `print("a")  # 说明` | 语句右侧，`#` 前至少一个空格 | 说明该行输出含义 |
| 文档注释 | `"""……"""` | 文件第一行开始 | 程序头信息、函数说明 |

### 1.3.3 常见用法与易错点

- **注释要写"为什么"，不只写"是什么"**。`# 输出提示` 价值低；`# 分隔线统一 32 个等号，与大屏模板对齐` 才有信息量。
- 三引号注释**不是**真正的注释语句，它本质是一个未被赋值的字符串；放在文件或函数开头时，Python 会把它记录为该文件/函数的文档字符串（`__doc__`），第 10 章会用到这一特性。
- 注释不能嵌套：`# 外层 # 内层` 中第二个 `#` 仍属注释内容，不是新注释。
- 注释掉的代码不会执行，可用它做"临时停用某行"的调试手段。

### 1.3.4 随堂示例：注释不参与运行

**核心要点**：验证三类注释的实际效果：独立成行的注释、行尾注释、被注释掉的语句都不产生输出，只有未被注释的 `print` 才输出。

```python demo1-2
# 这是独立成行的注释，Python 直接跳过
print("提示：前方施工，请减速")      # 行尾注释：说明本行含义
# print("这行被注释掉了，不会输出")
print("注释不影响程序结果")          # 三条 print 只生效两条
```

**预期输出**：

```text
提示：前方施工，请减速
注释不影响程序结果
```

**变式代码（迁移练习）**：把随堂示例的「注释掉一行」迁移为「注释 + 行尾注释 + 注释内伪代码」三种形态同时出现，验证它们都完全不参与运行。

```python demo1-2b
# 注释不会被编译：把一行代码注释掉，输出行数就少一行
print("第 1 行：程序开始")
# print("这行被注释，不输出")
print("第 2 行：统计完成")  # 行尾注释只影响本行右侧
# 注释里即使写着 print("假代码") 也不会执行
print("实际输出共 3 行")
```

**预期输出**：

```text
第 1 行：程序开始
第 2 行：统计完成
实际输出共 3 行
```

### 1.3.5 实操步骤（上机跟随）

1. 先不看代码，预测会输出几行；运行后确认是 3 行而不是 4 行或 5 行。
2. 把第 3 行的 `#` 删掉再运行，观察输出变成 4 行，理解「注释掉」就是让词法分析器跳过该行。
3. 把行尾注释 ` # 行尾注释只影响本行右侧` 整段删掉，确认该行输出内容一字不变。
4. 在注释里故意写一句 `print("不会输出")`，运行后确认终端没有多出内容。
5. 把注释改成说明业务口径（如 `# 断面流量按 5 分钟粒度汇总`），体会「写为什么」比「写做什么」更有价值。

### 1.3.6 常见问题 FAQ

| 现象 | 根因 | 处理 |
|---|---|---|
| 注释里的代码竟然执行了 | 引号或三引号没有成对闭合，注释块提前结束 | 检查配对；注释掉多行时逐行加 `#` 更稳妥 |
| 中文注释报编码错 | 文件保存成了非 UTF-8 且未声明编码 | 统一存成 UTF-8，Python 3 默认按 UTF-8 读取源文件 |
| 三引号里的文字出现在输出中 | 它被当成了字符串对象并传给了 `print` | 独立成句且未赋值时才作文档用；真要注释就逐行写 `#` |
| 注释越多程序越慢 | 误以为注释会被逐行解释 | 注释在词法分析阶段已丢弃，对运行速度无影响 |


## 1.4 知识点 1.3　转义字符与多行字符串

### 1.4.1 核心概念

有些字符无法直接写进字符串：换行、制表、引号本身、反斜杠。它们用**反斜杠加一个字母**表示，称为**转义字符**。Python 读到反斜杠时，不会原样输出，而是与后面的字符组合成一个特殊字符。

**多行字符串**用三个引号定义，字符串中的换行位置**就是**输出时的换行位置，因此可以用一条 `print` 输出整段文字。

**原理补充（概念深化）**：转义字符发生在**源码到字符串对象**的转换阶段：解释器读到反斜杠时，会连同后一个字符合并成一个新字符再存进内存，所以 `\n` 在字符串里只占**一个**字符位置，而不是两个。用 `len()` 对比 `"A\nB"` 与字面四个符号的长度就能验证这一点。这也解释了 Windows 路径为什么常出错——`\t` 会被当成制表符、路径里的 `\` 后面跟字母时会被吃掉，稳妥写法是写成 `\\`，或直接在字符串前加 `r` 前缀表示原始字符串。多行字符串则是把源码里的真实换行保留进对象，本质上等价于在每行之间插入 `\n`。因此「用 `\n` 拼出来」和「用三引号写出来的」是同一个对象，区别只在源码可读性，而不在运行结果。

### 1.4.2 语法要点

| 转义字符 | 含义 | 交通场景用途 | 示例输出 |
|---|---|---|---|
| `\n` | 换行 | 一条 `print` 内分行，如"自检完成 / 系统正常" | 光标移到下一行 |
| `\t` | 制表（跳到下一个制表位） | 车牌、时间、车位三列对齐 | 列间出现较大空隙 |
| `\\` | 一个反斜杠 | 输出 Windows 路径 `D:\traffic\...` | `D:\traffic` |
| `\"` | 一个双引号 | 文本中需要引号 | `"限速 60"` |
| `\'` | 一个单引号 | 外层用单引号时输出单引号 | `it's` |

**多行字符串写法**：

```text
print("""第一行
第二行
第三行""")
```

三条规则：① 第一个换行发生在 `"""` 之后；② 最后一个换行不产生，收尾 `"""` 要紧贴最后一行文字；③ 三引号内的缩进会原样输出。

### 1.4.3 常见用法与易错点

| 易错点 | 现象 | 原因与修正 |

| 路径只写一个反斜杠 | `D: raffic\parking`（`\t` 变成制表符） | `"D:\traffic"` 中的 `\t` 被解释为制表符，须写 `"D:\\traffic"` |

## 1.5 知识点 1.4　输出排版

### 1.5.1 核心概念

排版的目标是"让人一眼看清结构"。本章只用手工排版，三种手段：

1. **分隔线**：用重复字符写成固定长度的字符串，如 32 个等号；
2. **居中**：在标题前后补空格。先算标题显示宽度（汉字计 2 列、ASCII 计 1 列），再按公式「左空格 = (总宽 − 显示宽度) // 2」计算；差值为奇数时右边多 1 个空格，即左少右多；
3. **对齐**：用 `\t` 让同一列的起始位置一致，或用空格手工补齐。

第 4 章会讲 `f-string` 的 `:<10` `:>10` 精确对齐，届时可替换本章的手工排版；本章先建立"列要对齐"的意识。

**原理补充（概念深化）**：手工排版的本质是**让每一行的显示宽度可预测**。等宽字体下每个 ASCII 字符占一列、每个汉字占两列，所以「居中」要先算标题的显示宽度，再用 `(总宽 − 标题宽) ÷ 2` 补空格；一旦中间某一行多写了一个字符，整块版式就会肉眼可见地歪掉。这里藏着一个重要的工程观念：**版式是输出层的事，不该混进数据层**。本章把分隔线、空格、制表符直接写在 `print` 里，是为了先建立「列要对齐」的意识；到第 4 章学 f-string 的宽度与对齐标记后，就可以把「数据」和「显示宽度」拆开，同一个流量值能同时输出成终端表格、CSV 或报表而不必改数据本身。现在先记住一条检查口诀：上下分隔线同长、表头与数据用相同个数的 `\t`。

### 1.5.2 语法要点

| 手法 | 写法 | 说明 |
|---|---|---|
| 分隔线 | `print("=" * 32)` 属第 2 章；本章写 `print("================================")` | 直接数字符，保证上下两行等长 |
| 标题居中 | `print("        智慧交通出行提示")` | 前置 8 个空格，目视居中即可 |
| 列对齐 | `print("车牌号码\t入场时间\t车位编号")` | 表头与数据行使用**相同数量**的 `\t` |
| 收尾线 | `print("--------------------------------")` | 与标题线区分字符，形成视觉层次 |

### 1.5.3 常见用法与易错点

- **上下分隔线必须等长**，否则版式歪斜；用编辑器列号或数一数字符确认。
- 表头与数据行的 `\t` 数量必须一致；若某列文字宽度差异过大，可改用两个 `\t`，但要**整列统一**改。
- 中英文混排时，汉字占两列而英文字母占一列，`\t` 的对齐效果会出现轻微参差，属正常现象；正式报表应在第 4 章用格式化宽度控制，或改用表格控件。

### 1.5.4 随堂示例：分隔线与两列对齐

**核心要点**：验证手工排版的三条规则：上下分隔线字符数相同、标题两侧补空格居中、表头与数据行的 `\t` 数量一致。


### 1.5.6 常见问题 FAQ

| 现象 | 根因 | 处理 |
|---|---|---|
| 分隔线一长一短 | 两行分别手写了不同数量的字符 | 统一用同一个重复表达式，例如 `"=" * 24` |
| 列对齐时好时坏 | 中文占两列而 `\t` 按固定制表位跳格 | 本章先接受轻微参差，第 4 章用 f-string 宽度标记解决 |

| 改了数据版式就乱 | 把空格和制表符写死在数据字符串里 | 把排版放在输出阶段，数据保持原值 |


## 1.6 知识点 1.5　程序的保存与运行

### 1.6.1 核心概念

一段代码要能被反复运行，必须**存成文件**。Python 源文件以 `.py` 为扩展名，文件内容就是纯文本程序。本章提供两种运行方式：

1. **Jupyter 单元格**：改一格、按 `Shift + Enter` 立刻看结果，适合课堂跟做；
2. **脚本文件**：在终端执行 `python 文件名.py`，适合提交作业与真实部署。

**原理补充（概念深化）**：`.py` 文件只是**纯文本**，里面按从上到下的顺序写着语句；`python 文件名.py` 启动后，解释器先整体编译成字节码，再逐条执行，因此「第几行先输出」完全由源码顺序决定，与 Notebook 里按单元格执行不同——Notebook 可以跳着跑，脚本不行。这也是为什么脚本必须把「读入 → 计算 → 输出」按顺序写全，缺一步后面就都是空的。另一个常踩的差别是**工作目录**：脚本启动时以「你执行它的那个目录」为当前目录，而不是文件所在目录，所以相对路径的数据文件常找不到；第 8 章讲文件操作、第 14 章讲 `pathlib` 时会专门处理。退出码为 0 表示正常跑完，非 0 表示中途出错，这个约定后面做自动校验时会反复用到。

### 1.6.2 语法要点

| 事项 | 规范 | 说明 |
|---|---|---|
| 文件扩展名 | `.py` | 不可写成 `.txt` |
| 文件编码 | UTF-8 | 含中文的源文件必须用 UTF-8 保存，否则运行时报 `SyntaxError: Non-UTF-8 code` |
| 文件命名 | 英文或拼音 + 下划线，如 `case1_信息板提示.py` | 避免空格与特殊符号，便于命令行执行 |
| 运行命令 | `python 文件名.py` | 需在文件所在目录执行，或用绝对路径 |
| 输出位置 | 终端 / 单元格下方 | 脚本运行结果显示在终端，不是弹窗 |

### 1.6.3 常见用法与易错点

- 双击 `.py` 文件可能一闪而过：程序运行完窗口立即关闭。应在终端中运行，或在末尾加 `input()` 暂停（第 2 章）。
- `python: command not found`：命令名可能是 `python3`，用 `python3 文件名.py` 试。
- Jupyter 中修改代码后未重新运行，看到的是上一次结果；判断依据是单元格左侧的执行序号 `[n]` 是否递增。
- 本章代码无输入，可放心"运行全章"。

## 本章小结

- **输出**：`print("文本")` 一次输出一行并自动换行；引号内的内容原样输出，引号不显示。
- **注释**：`#` 单行注释解释"为什么"；三引号文档注释放在文件开头写程序头信息。
- **转义**：`\n` 换行、`\t` 对齐、`\\` 输出反斜杠；路径中的反斜杠必须写成双反斜杠。
- **多行**：三引号字符串保留源码换行，一条 `print` 输出多行，收尾引号紧贴文字。
