# 第一部分　知识讲解

## 12.1 场景导入：车型不同，能不能不写四遍 if

车型不同，限速不同，费率也不同：小客车限速 120、货车限速 80 且费率上浮、客车限速 100。若用 `if vtype == "货车"` 逐个判断，每增加一种车型就要改一遍所有分支。

继承让"差异"只写在子类里，多态让调用方**不必关心具体车型**——同一句 `v.fee(120)`，货车自动算 1.8 倍、客车自动算 1.2 倍，主程序一个字都不用改。这正是交通仿真、收费系统、设备管理的基础设计。

## 12.2 知识点 12.1　封装回顾

### 12.2.1 核心概念

第 11 章已经建立封装的基本手法：

| 手法 | 作用 |
|---|---|
| `self.__x` 私有属性 | 限制外部直接改值 |
| `get_x()` / `set_x()` 公有方法 | 提供受控读写入口 |
| 校验写在 `set_x()` 内 | 保证任何修改都经过校验 |
| `__check()` 私有方法 | 内部复用校验逻辑 |

本章的继承体系中，**父类负责封装共性**（如 `Vehicle.plate`、`Vehicle.speed`），**子类只重写差异**——这就是封装与继承的配合方式。

**原理补充（概念深化）**：「私有」并不是加密：双下划线属性在类定义时被解释器改名成「下划线加类名加原名」的形式，外部仍可用改名后的名字或对象字典看到它。改名的真正作用是避免子类意外覆盖父类的同名属性。内存里每个实例只有一张属性字典，父类的共性数据与子类的扩展属性平铺其中，并不存在两层对象。区间约束必须写进唯一的写入入口（构造方法与设值方法），否则构造时直接赋值就绕过校验，非法车速会悄悄进入仿真。类外直接给同名属性赋值并不报错，只新建一个普通键，与改名后的私有项是两码事——这正是初学者觉得「改了却没生效」的根因。

### 12.2.2 常见用法与易错点

| 易错点 | 现象 | 修正 |
|---|---|---|
| 子类直接改父类私有属性 | `AttributeError`（名称已被改写为 `_父类名__x`） | 用父类提供的 `get` / `set` |
| 父类属性全设私有 | 子类无法参与计算，只能靠接口绕 | 共性数据用公有属性，敏感数据用私有 |
| 忘记在 `__init__` 中校验 | 非法初始值进入对象 | 构造末尾调用 `__check()` |

### 12.2.4 随堂示例：封装：把约束放进方法里

**核心要点**：验证封装的价值：外部只调方法、不碰属性，区间约束（0~120）只在类内写一次，任何调用方都无法绕过。

```python demo12-1
class Vehicle:
    def __init__(self, plate, speed=0):
        self.plate = plate
        self.__speed = speed

    def accelerate(self, delta):
        self.__speed = min(self.__speed + delta, 120)   # 上限约束在类内
        return self.__speed

    def get_speed(self):
        return self.__speed

v = Vehicle("京A12345", 100)
print("初始车速：", v.get_speed())
print("加速 50：", v.accelerate(50), "（被限制在 120）")
print("再加速 30：", v.accelerate(30))
```

**预期输出**：

```text
初始车速： 100
加速 50： 120 （被限制在 120）
再加速 30： 120
```

**变式代码（迁移练习）**：把随堂示例的单向上限约束迁移为"双向区间夹逼 + 名称改写验证"：新增构造期校验与类外直改对照，验证私有属性被改名后外部同名赋值动不了真实值。

```python demo12-1b
class Gantry:  # 门架测速：车速私有，区间约束只在类内写一次
    def __init__(self, road, v):
        self.road = road
        self.__v = max(0, min(v, 120))  # 写入前把 150 夹到 120
g = Gantry("G15 门架", 150)
print("对象字典：", g.__dict__)  # 私有 __v 被改名为 _Gantry__v
g.__v = 999  # 类外不改名，只是新建一个键，动不了私有值
print("真实车速仍是：", g._Gantry__v)
print("外部直改产生的键：", "__v" in g.__dict__)
```

**预期输出**：

```text
对象字典： {'road': 'G15 门架', '_Gantry__v': 120}
真实车速仍是： 120
外部直改产生的键： True
```

### 12.2.5 实操步骤（上机跟随）

1. 运行后观察首行 `对象字典` 中私有键已被写成 `_Gantry__v`，而不是 `__v`。
2. 核对构造参数 150 打印出的车速是 120，说明 `min(v, 120)` 在写入 `__v` 之前就生效。
3. 观察末行 `外部直改产生的键： True`，确认类外的 `g.__v = 999` 新建了一个普通键。
4. 核对第二行 `真实车速仍是： 120`，证明改写后的 `_Gantry__v` 没有被那行外部赋值改变。
5. 试着把 `g._Gantry__v` 直接改成 60 再打印第二行，观察车速真的变 60，理解「私有只是改名、不是加密」。

### 12.2.6 常见问题 FAQ

| 现象 | 根因 | 处理 |
|---|---|---|
| `AttributeError: 'Gantry' object has no attribute '__v'` | 私有名已被改写为 `_Gantry__v`，类外用原名访问不到 | 通过类内方法读取，或用改写后的名字 `g._Gantry__v` |
| 外部写 `g.__v = 999` 后读到的车速仍是原值 | 类外不触发名称改写，这行只新建一个普通属性 `__v` | 一律通过 `set_speed()` 修改，不要直接赋值 |
| 构造时传入 150，车速却没被限制 | 校验只写在 `set_speed()`，构造时直接赋给 `self.__v` 绕过了校验 | 构造末尾也调用统一的校验入口 |
| 子类里改 `self.__v` 对父类数据不起作用 | 私有名按定义它的类名改写，子类的 `self.__v` 是 `_子类名__v`，与父类不是同一项 | 父类提供共有的 `get/set` 方法供子类调用 |
| 打印 `g` 出现 `<... object at 0x...>` | 未定义 `__str__`，打印的是含内存地址的对象默认 repr | 自定义 `__str__` 或打印具体属性 |


## 12.3 知识点 12.2　继承与 `super()`

### 12.3.1 核心概念

```text
class Vehicle:            # 父类（基类）
    ...

class Truck(Vehicle):     # 子类（派生类）：括号内写父类名
    ...
```

- 子类**自动获得**父类的全部公有属性与方法；
- 子类可新增自己的属性与方法；
- `super()` 用于**调用父类的同名方法**，最常用的是 `super().__init__(...)`。

**原理补充（概念深化）**：继承不是把父类代码复制一份，而是查找：每个类都带一张 MRO 表，调用方法时按「子类、父类、object」依次找，找到即停，父类方法始终只存一份。内存里子类实例只有一张属性字典，父、子属性平铺其中；super 语句只是以这个实例为 self 去执行父类初始化，把车牌写进同一张字典。所以 super 不是调用父类对象，而是沿 MRO 从下一站继续找方法，必须放在子类构造方法的首行，否则父类用到的属性还没写入就会报错。isinstance 返回真也不是类型转换，而是沿继承链比对。

### 12.3.2 语法要点

| 场景 | 写法 | 说明 |
|---|---|---|
| 单继承 | `class Bus(Vehicle):` | 括号内是父类 |
| 调用父类构造 | `super().__init__(plate, speed)` | **必须在使用 `self` 之前** |
| 调用父类方法 | `super().fee(km, rate)` | 取父类实现的结果再加工 |
| 判断继承关系 | `isinstance(t, Vehicle)` | 子类实例也是父类实例 |

**多继承**：`class A(B, C):` 合法，按 MRO 顺序查找方法，但本章不展开——交通场景中单继承已足够表达"车型 / 设备 / 车道"的分类。

### 12.3.3 常见用法与易错点

| 易错点 | 现象 | 修正 |
|---|---|---|
| 子类 `__init__` 忘记 `super()` | `AttributeError: 'Truck' object has no attribute 'plate'` | 首行调用 `super().__init__(...)` |
| `super()` 放在赋值之后 | 可能覆盖已设值，逻辑混乱 | 放首行 |
| 父类名硬编码 `Vehicle.__init__(self, ...)` | 改父类名要改多处 | 用 `super()` |
| 误以为子类会"复制"父类代码 | 实际是"查找" | 理解方法解析顺序 |

### 12.3.4 随堂示例：继承：子类复用父类能力

**核心要点**：验证 `class 子类(父类)` 自动获得父类方法，`super().__init__()` 复用父类初始化；`isinstance()` 认定子类对象同时属于父类。

```python demo12-2
class Vehicle:
    def __init__(self, plate):
        self.plate = plate

    def limit(self):
        return 120

    def info(self):
        return self.plate + " 限速 " + str(self.limit()) + " km/h"

class Truck(Vehicle):
    def __init__(self, plate, load):
        super().__init__(plate)         # 复用父类初始化
        self.load = load

    def limit(self):
        return 80                       # 重写：货车限速更低

t = Truck("京B67890", 18)
print(t.info())
print("载重：", t.load, "吨")
print("是 Vehicle 的实例吗：", isinstance(t, Vehicle))
```

**预期输出**：

```text
京B67890 限速 80 km/h
载重： 18 吨
是 Vehicle 的实例吗： True
```

**变式代码（迁移练习）**：把随堂示例的"货车重写 limit"迁移为"救护车只继承不重写 + 打印 MRO 链"，验证继承是按查找链复用父类方法而非复制代码，且父、子属性共存于同一实例字典。

```python demo12-2b
class Vehicle:  # 车辆基类：共性数据与限速写在父类
    def __init__(self, plate): self.plate = plate   # 一行方法体
    def limit(self): return 120
class Ambulance(Vehicle):  # 子类：括号写父类，方法靠"查找"而非复制
    def __init__(self, plate, level):
        super().__init__(plate)  # 首行复用构造，plate 才有值
        self.level = level
a = Ambulance("京A急救01", 1)
print("车牌：", a.plate, "；限速：", a.limit(), "；等级：", a.level)
print("继承链：", [c.__name__ for c in Ambulance.__mro__], "；是 Vehicle 吗：", isinstance(a, Vehicle))
```

**预期输出**：

```text
车牌： 京A急救01 ；限速： 120 ；等级： 1
继承链： ['Ambulance', 'Vehicle', 'object'] ；是 Vehicle 吗： True
```

### 12.3.5 实操步骤（上机跟随）

1. 运行后观察 `继承链` 打印为 `['Ambulance', 'Vehicle', 'object']`，确认查找顺序是子类在前、父类在后。
2. 观察 `限速： 120`：子类没写 `limit()` 却拿到父类返回值，证明是「查找」而非复制代码。
3. 观察 `车牌： 京A急救01`，说明 `super().__init__(plate)` 把 `plate` 写进了实例字典。
4. 观察 `等级： 1` 与车牌同时存在，说明父、子属性都在同一个 `a.__dict__` 里。
5. 把 `super().__init__(plate)` 注释掉再运行，观察报错行正是访问 `a.plate` 的那行 `print`。
6. 观察 `是 Vehicle 吗： True`，确认子类实例同时被认定为父类实例。

### 12.3.6 常见问题 FAQ

| 现象 | 根因 | 处理 |
|---|---|---|
| `AttributeError: 'Ambulance' object has no attribute 'plate'` | 子类 `__init__` 忘了 `super().__init__(plate)`，父类初始化没执行 | 在子类 `__init__` 首行补 `super().__init__(...)` |
| `super()` 放在赋值之后，父类值把已设的属性覆盖 | 父类初始化后执行会重写同名字段，逻辑混乱 | 把 `super().__init__` 放到首行 |
| 改父类名后多处报 `NameError` | 硬编码了 `Vehicle.__init__(self, ...)`，父类名写死在多处 | 改用 `super()`，不写死父类名 |
| 以为子类「复制」了父类方法，改父类后子类行为不变 | 实际是运行时沿 MRO 查找，父类方法只有一份 | 理解方法解析顺序，改动父类会即时影响所有子类 |
| `isinstance(a, Vehicle)` 期望 `False` 却是 `True` | `isinstance` 沿继承链判断，子类实例也算父类实例 | 需要精确类型时改用 `type(a) is Vehicle` |


## 12.4 知识点 12.3　方法重写

### 12.4.1 核心概念

子类定义**与父类同名的方法**即"重写"（override）：调用时优先使用子类版本，父类版本仍可通过 `super()` 调回。

重写有三种典型用法：

| 用法 | 说明 | 案例 |
|---|---|---|
| 完全替换 | 子类给出全新实现 | `Car.limit()` 返回 120 |
| 扩展 | `super().方法()` 取父类结果再加工 | `Truck.fee()` 乘 1.8 |
| 追加信息 | 父类字符串 + 子类补充 | `Truck.info()` 加"载重" |

**原理补充（概念深化）**：重写是同名方法在子类 MRO 中排在前面：解释器先命中子类版本，父类版本并未删除，只是被遮蔽，仍可用 super 取回。super 从 MRO 的下一站开始查找，只取一次父类结果，不会绕回子类导致无限递归，所以「先拿父类结果再乘系数」的扩展写法是安全的。方法名与参数表须与父类一致，否则按父类签名传参会报 `TypeError`，或变成新方法让父类版本仍被调用。最容易埋雷的是漏写 `return`：函数会隐式返回 `None`，调用方拿它参与运算才报错，排查很晚。

### 12.4.2 语法要点

- 方法名、参数表应与父类**保持一致**（参数可增加默认值，但不建议改顺序）；
- `super().info()` 只能取到父类实现，不会再次触发子类的 `info()`（避免无限递归）；
- 重写后父类方法依然存在，可用 `父类名.方法(obj)` 显式调用（不推荐）。

### 12.4.3 常见用法与易错点

| 易错点 | 现象 | 修正 |
|---|---|---|
| 子类方法名拼错 | 变成新方法，父类版本仍被调用 | 对照父类签名检查 |
| `super().fee(km)` 漏参数 | `TypeError` | 参数与父类一致 |
| 在 `__str__` 中调 `self.info()` | 逻辑绕、易递归 | 直接用 `super().info()` |
| 重写后忘记返回 | 调用方得到 `None` | 每个分支都 `return` |

### 12.4.4 随堂示例：方法重写：替换与扩展

**核心要点**：验证重写的两种形态：完全替换（直接给新实现）与扩展（先 `super()` 取父类结果再加工），二者对外接口保持一致。

```python demo12-3
class Vehicle:
    def fee(self, km, rate=0.5):
        return round(km * rate, 2)

class Bus(Vehicle):
    def fee(self, km, rate=0.5):
        return round(km * rate * 1.2, 2)     # 替换：直接新实现

class Truck(Vehicle):
    def fee(self, km, rate=0.5):
        base = super().fee(km, rate)         # 扩展：先取父类结果
        return round(base * 1.8, 2)

print("小客车 120km：", Vehicle().fee(120))
print("客车   120km：", Bus().fee(120))
print("货车   120km：", Truck().fee(120))
```

**预期输出**：

```text
小客车 120km： 60.0
客车   120km： 72.0
货车   120km： 108.0
```

**变式代码（迁移练习）**：把随堂示例的单一费率重写迁移为"替换 / 扩展 / 追加信息"三种形态同场对比，验证 `super()` 取父类结果不递归，且三种写法对外接口 `fee` / `info` 完全一致。

```python demo12-3b
class Toll:  # 通行费基类：给出基准实现
    def fee(self, km): return round(km * 0.5, 2)
    def info(self): return "基准费率 0.5"
class Etc(Toll):  # 完全替换：直接给新实现，不调父类
    def fee(self, km): return round(km * 0.5 * 0.95, 2)
class Truck(Toll):  # 扩展：先 super 取父类结果再加工
    def fee(self, km): return round(super().fee(km) * 1.8, 2)
    def info(self): return super().info() + "，货车上浮"  # 追加信息且不会递归
for label, t in [("基准", Toll()), ("ETC", Etc()), ("货车", Truck())]:
    print(label, "120km 费：", t.fee(120), "；", t.info())
```

**预期输出**：

```text
基准 120km 费： 60.0 ； 基准费率 0.5
ETC 120km 费： 57.0 ； 基准费率 0.5
货车 120km 费： 108.0 ； 基准费率 0.5，货车上浮
```

### 12.4.5 实操步骤（上机跟随）

### 12.4.6 常见问题 FAQ

| 现象 | 根因 | 处理 |
|---|---|---|
| 子类方法名拼错，父类版本仍被调用 | 拼错的名字成了新方法，未构成重写 | 对照父类签名逐个核对方法名 |
| `super().fee(km)` 报 `TypeError` 缺参数 | 漏传父类要求的参数，或参数顺序改动 | 参数表与父类保持一致 |
| 调用重写方法得到 `None` | 某个分支漏写 `return`，函数隐式返回 `None` | 每个分支都显式 `return` |
| 担心 `super().info()` 会无限递归 | 误以为 super 会重新调用子类方法 | `super()` 从 MRO 下一站取父类实现，不会绕回子类 |
| 在 `__str__` 里调 `self.info()` 逻辑绕、易递归 | `self.info()` 可能再次触发相关链路 | 直接用 `super().info()` 拼字符串 |


## 12.5 知识点 12.4　多态与接口约定

### 12.5.1 核心概念

**多态**：同一句调用，作用在不同类型的对象上产生不同行为。前提是"这些对象共用同一个方法名"——这个共同的方法名就是**接口**。

```text
for d in devices:
    print(d.status())      # 不判断类型，各自实现
```

`poll()` 完全不知道设备是灯、情报板还是道闸，新增"毫米波雷达"时**只需新增一个子类**，`poll()` 一行都不用改。

**接口约定**：基类方法直接 `raise NotImplementedError("子类必须实现…")`，强制子类重写。若子类忘记实现，调用时立刻报错，而不是静默返回错误结果。

**原理补充（概念深化）**：多态不靠类型分支，而靠「所有对象都实现同名方法」这份接口约定：那句状态调用在运行前并不知道对象是什么，解释器运行时才按对象实际类型的方法表动态分派。因此新增设备只要也有同名方法，主循环一个字都不用改。基类为何要抛出未实现异常而非返回空值？因为空值是合法返回值，子类漏实现时会被静默打印、错误极晚才暴露；抛异常则第一次调用就拦截。反模式是在循环里写 isinstance 分支，那等于退回第 3 章，每加一种设备都要改调用方。接口名也必须统一，写成别的名字就会分派失败。

### 12.5.2 语法要点

| 写法 | 作用 |
|---|---|
| 基类 `def status(self): raise NotImplementedError(...)` | 声明"必须由子类实现" |
| 子类 `def status(self): return "…"` | 提供具体实现 |
| 统一循环 `for d in devices: d.status()` | 调用方不判断类型 |

### 12.5.3 常见用法与易错点

| 易错点 | 现象 | 修正 |
|---|---|---|
| `poll()` 里写 `isinstance` 分支 | 退化为第 3 章写法，失去多态 | 只依赖共同方法名 |
| 子类漏实现基类方法 | 调用时 `NotImplementedError` | 补齐实现 |
| 方法名不一致（`get_status` / `status`） | 多态失效 | 统一命名 |
| 基类方法返回 `None` 而非抛错 | 静默错误，难发现 | 用 `raise NotImplementedError` |

## 12.6 知识点 12.5　`isinstance()` 与 `type()`

### 12.6.1 核心概念

| 函数 | 判断内容 | 子类实例的结果 |
|---|---|---|
| `isinstance(obj, 类)` | 是不是该类**或其子类**的实例 | `True` |
| `type(obj) is 类` | 类型**精确**等于该类 | `False` |

因此在"按类型分支"时，`isinstance` 更符合直觉（货车"是"车辆）；`type()` 用于需要精确判定的场景（如日志记录精确类型名）。

`isinstance` 的第二个参数可以是**元组**：`isinstance(x, (int, float))` 表示"任一类型即可"。

**原理补充（概念深化）**：差别不在「宽松还是严格」，而在判断路径：isinstance 沿实例类型的 MRO 链逐个比对，链上任一环节命中即为真，所以三级链里的特种车实例也会被判为货车；type 加 is 只做确切类型对象的身份比较，差一个子类就为假。这也解释了第二参数可用元组——本质是对每项各做一次链上比对，写成列表会报类型错误。取类型名得到的是类的名字字符串，适合日志；直接打印对象会得到含内存地址的默认表示，每次运行都变、无法核对。更要紧的是：能不用类型判断就不用，一旦按类型写分支，新增车型就得改分支，与多态相悖。

### 12.6.2 语法要点

| 写法 | 结果（`t = Truck(...)`） |
|---|---|
| `isinstance(t, Truck)` | `True` |
| `isinstance(t, Vehicle)` | `True` |
| `type(t) is Vehicle` | `False` |
| `type(t).__name__` | `"Truck"` |

### 12.6.3 常见用法与易错点

| 易错点 | 现象 | 修正 |
|---|---|---|
| 用 `type(x) == Vehicle` 判子类 | 子类被判为"不是车辆" | 用 `isinstance` |
| `isinstance` 第二参数写成列表 | `TypeError` | 用元组 |
| 过度使用类型判断 | 代码僵硬，新增类型要改多处 | 优先用多态 |

### 12.6.4 随堂示例：isinstance 与 type 的取舍

**核心要点**：验证二者差异：`isinstance()` 沿继承链判断（子类对象也算父类），`type()` 只认精确类型；接口判断用前者更安全。

```python demo12-5
class Vehicle:
    pass

class Truck(Vehicle):
    pass

t = Truck()
print("type(t).__name__：", type(t).__name__)
print("isinstance(t, Truck)：", isinstance(t, Truck))
print("isinstance(t, Vehicle)：", isinstance(t, Vehicle))
print("type(t) is Vehicle：", type(t) is Vehicle)

items = [Vehicle(), Truck()]
for x in items:
    print(type(x).__name__, "是 Vehicle 吗：", isinstance(x, Vehicle))
```

### 12.6.6 常见问题 FAQ

| 现象 | 根因 | 处理 |
|---|---|---|
| 子类对象用 `type(x) == Vehicle` 判成「不是车辆」 | `type` 只做精确类型比较，不含子类 | 改用 `isinstance(x, Vehicle)` |

| 新增车型后按类型写的分支要改多处 | 过度使用类型判断，代码僵硬 | 优先用多态，类型判断只用于边界/日志 |
| 打印对象出现 `<... object at 0x...>` | 未自定义 `__str__`，用了含内存地址的默认 repr | 打印 `type(x).__name__` 或具体属性 |
| 以为 `isinstance(v, (Truck, int))` 会把字符串也判成数值 | 混淆了「任一命中即可」与类型层级 | 元组表示对每一项做链上比对，与继承无关的类型仍为 `False` |

```python case1_车型继承.py
        self.speed = speed

    def limit(self):

        return 120

        """基础通行费"""
        return round(km * rate, 2)

    def info(self):
        return self.plate + " 限速 " + str(self.limit()) + " km/h"

    def limit(self):
        return 80

        base = super().fee(km, rate)       # 先算基础费用
        return round(base * 1.8, 2)        # 货车按 1.8 倍计费

    def info(self):
        return super().info() + "，载重 " + str(self.load) + " 吨"


class Bus(Vehicle):
    """客车"""

    def limit(self):
        return 100

    def fee(self, km, rate=0.5):
        return round(km * rate * 1.2, 2)
```

```python case2_设备多态.py
        self.code = code

    def status(self):
        raise NotImplementedError("子类必须实现 status()")

    def refresh(self):
        raise NotImplementedError("子类必须实现 refresh()")


class Light(SignalDevice):

    def refresh(self):

class VariableSign(SignalDevice):
    """可变情报板"""

    def __init__(self, code, text="限速 60"):
        super().__init__(code)
        self.text = text

    def status(self):
        return "情报板 " + self.code + " 显示 <" + self.text + ">"

    def refresh(self):
        return "情报板 " + self.code + " 已刷新显示内容"


class Barrier(SignalDevice):
    """道闸"""

    def __init__(self, code, opened=False):
        super().__init__(code)
        self.opened = opened

    def status(self):
        state = "抬起" if self.opened else "落下"
        return "道闸 " + self.code + " 当前" + state

    def refresh(self):
        self.opened = not self.opened
        return "道闸 " + self.code + " 已切换为" + ("抬起" if self.opened else "落下")


def poll(devices):
    """统一巡检：不判断具体类型"""
    print("=== 设备巡检开始，共 " + str(len(devices)) + " 台 ===")
    for d in devices:
        print("[状态]", d.status())
        print("[指令]", d.refresh())
    print("=== 巡检结束 ===")


devices = [

    VariableSign("V-07", "前方事故，减速慢行"),
    Barrier("B-03"),
    Light("L-02", "黄灯"),
]

poll(devices)
print()
print("第二轮巡检（道闸状态已翻转）：")
poll(devices)
```

## 答案 12-1　ETC 车道与人工车道

> 对应 **练习 12-1**（第三部分）

### 参考代码

```python practice1_车道继承.py
# ---------- 第 12 章 面向对象编程（下）· 练习 12-1 参考答案：ETC 车道与人工车道 ----------
# 对应知识点：12.2 继承与 super().__init__、12.3 重写（通行能力 / 计费 / 信息追加）
# 功能说明：由车道基类派生 ETC 车道与人工车道，分别重写通行能力与收费规则

class Lane:
    """车道基类"""

    def __init__(self, code):
        self.code = code

    def capacity(self):
        return 400

    def fee(self, km, rate=0.5):
        return round(km * rate, 2)

    def info(self):
        return self.code + " 通行能力 " + str(self.capacity()) + " 辆/h"


class EtcLane(Lane):
    """ETC 车道"""

    def __init__(self, code, device_ok=True):
        super().__init__(code)
        self.device_ok = device_ok

    def capacity(self):
        return 1500

    def fee(self, km, rate=0.5):
        return round(super().fee(km, rate) * 0.95, 2)

    def info(self):
        state = "正常" if self.device_ok else "故障"
        return super().info() + "，设备" + state


class ManualLane(Lane):
    """人工车道"""

    def capacity(self):
        return 400

    def info(self):
        return super().info() + "，人工发卡"


lanes = [EtcLane("E-01"), EtcLane("E-02", device_ok=False), ManualLane("M-01")]

for lane in lanes:
    print(lane.info(), "| 200km 费用", lane.fee(200), "元")

print()
print("ETC 与人工通行能力比：", round(EtcLane("X").capacity() / ManualLane("Y").capacity(), 2))
print("是否车道子类：", isinstance(lanes[0], Lane))
```

### 运行结果

```text
E-01 通行能力 1500 辆/h，设备正常 | 200km 费用 95.0 元
E-02 通行能力 1500 辆/h，设备故障 | 200km 费用 95.0 元
M-01 通行能力 400 辆/h，人工发卡 | 200km 费用 100.0 元

ETC 与人工通行能力比： 3.75
是否车道子类： True
```

### 解析

1. **重写的三种用法齐备**：`capacity` 是完全替换（1500 vs 400）；`fee` 是扩展（父类结果 × 0.95）；`info` 是追加（父类描述 + 设备状态）。
2. **`super().fee(km, rate)` 的位置**：必须先拿到父类结果再乘折扣。若写成 `round(km * rate * 0.95, 2)`，则与父类的计费公式重复实现，父类改费率时子类会失同步。
3. **故障车道仍能算费**：本题只要求"标注状态"，因此 `fee()` 未对 `device_ok` 做拦截；真实系统中应在 `fee()` 内判断 `device_ok` 并返回 `-1` 或抛异常——这是"业务规则放哪一层"的设计问题，值得课堂讨论。
4. **`isinstance(lanes[0], Lane)`**：`EtcLane` 实例也是 `Lane` 实例，这正是多态能成立的原因。

### 常见错误

| 错误现象 | 原因 | 修正 |
|---|---|---|
| `AttributeError: code` | `EtcLane.__init__` 漏 `super()` | 补 `super().__init__(code)` |
| 费用 190.0 | 折扣乘了两次 | 只乘一次 0.95 |
| 人工车道也打 95 折 | `ManualLane` 继承了 `EtcLane` | `ManualLane(Lane)` |
| 比值 3.75 变成 0.27 | 分子分母颠倒 | ETC ÷ 人工 |

## 答案 12-2　充电设施的多态计费

> 对应 **练习 12-2**（第三部分）

### 参考代码

```python practice2_充电桩多态.py
# ---------- 第 12 章 面向对象编程（下）· 练习 12-2 参考答案：充电设施的多态计费 ----------
# 对应知识点：12.4 多态与基类统一实现、12.3 方法重写、6.x 模板方法思想
# 功能说明：由充电桩基类派生快充与慢充，用统一接口按不同电价与功率计算充电费用

class Charger:
    """充电桩基类"""

    def __init__(self, code):
        self.code = code

    def power(self):
        return 7

    def price(self):
        return 0.6

    def overtime_fee(self, minutes):
        return 0

    def settle(self, kwh, minutes):
        energy_fee = round(kwh * self.price(), 2)
        service = round(energy_fee * 0.1, 2)
        ot = self.overtime_fee(minutes)
        return round(energy_fee + service + ot, 2)

    def info(self):
        return self.code + " " + str(self.power()) + "kW 单价 " + str(self.price()) + " 元/kWh"


class SlowCharger(Charger):
    def power(self):
        return 7

    def price(self):
        return 0.6


class FastCharger(Charger):
    def power(self):
        return 60

    def price(self):
        return 1.0


class SuperCharger(Charger):
    def power(self):
        return 250

    def price(self):
        return 1.6

    def overtime_fee(self, minutes):
        if minutes > 60:
            return (minutes - 60) * 2
        return 0


chargers = [SlowCharger("C-01"), FastCharger("C-02"), SuperCharger("C-03")]

for c in chargers:
    total = c.settle(35, 85)
    print(c.info(), "| 35kWh/85min 应收", total, "元")

print()
print("超充超时费：", SuperCharger("C-03").overtime_fee(85), "元")
print("慢充超时费：", SlowCharger("C-01").overtime_fee(85), "元")
```

### 运行结果

```text
C-01 7kW 单价 0.6 元/kWh | 35kWh/85min 应收 23.1 元
C-02 60kW 单价 1.0 元/kWh | 35kWh/85min 应收 38.5 元
C-03 250kW 单价 1.6 元/kWh | 35kWh/85min 应收 111.6 元

超充超时费： 50 元
慢充超时费： 0 元
```

### 解析

1. **模板方法**：`settle()` 只在基类写一次，内部依次调用 `self.price()` 与 `self.overtime_fee()`。运行时 `self` 是子类实例，因此自动绑定到子类实现——**多态不仅在调用方生效，在类内部同样生效**。
2. **计算核对（超充）**：电费 35 × 1.6 = 56.0；服务费 56 × 10% = 5.6；超时费 (85 − 60) × 2 = 50；合计 111.6 元。
3. **未重写即继承**：慢充、快充不写 `overtime_fee`，直接继承"返回 0"，因此无超时费。这体现"子类只写差异"。
4. **新增桩型的成本**：若增加"换电站"，只需新建子类并重写 `power` / `price`，`settle()` 与主循环都无需改动——这就是多态的可扩展性。

### 常见错误

| 错误现象 | 原因 | 修正 |
|---|---|---|
| 超充 61.6 元 | 漏了超时费 | `settle` 加 `self.overtime_fee()` |
| 慢充也收超时费 | `overtime_fee` 在基类里写了 2 元/分钟 | 基类返回 0 |
| 三个桩结果相同 | `settle` 里写死单价 | 用 `self.price()` |
| 服务费按 10 元固定 | 混淆比例与定额 | `energy_fee * 0.1` |

| 项 | 分值 | 观察点 |
|---|---|---|
| 基类结构 | 3 | 四个方法，`settle` 为模板 |
| 子类重写 | 4 | 功率、单价、超时费各自正确 |
| 结算结果 | 2 | 23.1 / 38.5 / 111.6 |
| 多态调用 | 1 | 主循环无类型判断 |

## 本章小结

- **封装**：私有属性 + 公有 `get` / `set`，校验写在唯一入口；子类通过接口访问父类私有数据。
- **继承**：`class 子类(父类)`；子类 `__init__` 首行 `super().__init__(...)`。
- **重写**：同名方法覆盖父类，三种用法——完全替换、`super()` 扩展、追加信息。
- **多态**：同一方法名、不同实现；调用方只依赖接口，新增类型不改调用方。
- **接口约定**：基类 `raise NotImplementedError` 强制子类实现，漏实现立即报错。
- **类型判断**：`isinstance` 含子类，`type()` 精确匹配；能不用类型判断就不用。
